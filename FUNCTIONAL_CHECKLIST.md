## Функціональна коректність та матриця виконання (C1)

У цій таблиці наведено список функціональних вимог для кожного учасника команди згідно з роадмапою проєкту Smart Planter та їхній поточний статус виконання.

### Учасник 1: Backend / Database / System Architecture

| ID    | Опис вимоги / Функціонал                                            | Статус | Примітка                        |
| ----- | ------------------------------------------------------------------- | ------ | ------------------------------- |
| BE-01 | REST API для авторизації та керування користувачами (JWT)           | Працює | /api/v1/auth                    |
| BE-02 | CRUD операції для рослин (створення, читання, оновлення, видалення) | Працює | /api/v1/plants                  |
| BE-03 | Прийом та збереження даних телеметрії від IoT-пристроїв             | Працює | /api/v1/telemetry               |
| BE-04 | Автоматична генерація алертів при виході показників за норму        | Працює | Сповіщення про низьку вологість |
| BE-05 | WebSockets / SignalR сервер для real-time оновлення даних           | Працює | WSS стримінг                    |

### Приймальні тест-кейси (Acceptance Test Cases)

1. Авторизація та допуск: Незареєстрований користувач бачить модальне вікно входу. Після входу відкривається доступ до додавання нових вазонів. — PASSED
2. Передача телеметрії: При відправці даних з емулятора графік та показники оновлюються в режимі реального часу. — PASSED
3. Полив рослини: Натискання кнопки «Зафіксувати полив» надсилає команду на сервер, блокує кнопковий спам і завантажує актуальну телеметрію. — PASSED
4. PWA Офлайн: При вимкненні мережі застосунок завантажує каркас з кешу і показує плашку OfflineBanner. — PASSED
