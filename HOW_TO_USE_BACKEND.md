# Руководство по интеграции с Backend API (Smart-Planter)

### Базовые адреса и протоколы
- **REST API (Docker):** `http://localhost:8000/api/v1`
- **REST API (Local):** `http://localhost:5168/api/v1`
- **WebSocket Hub (SignalR):** `/hubs/telemetry`
- **Формат обмена данными:** `application/json`
- **Формат дат:** ISO 8601 UTC (`YYYY-MM-DDTHH:mm:ssZ`)

---

### 1. Пользователи (`/users`)

#### `POST /users/register`
- **Назначение:** Регистрация пользователя. Фронтенд вызывает при создании аккаунта, Telegram-бот — при первом старте (`/start`), генерируя пароль автоматически.
- **Тело запроса:**
```json
{
  "username": "gardener_1",
  "password": "secret_password"
}
```

* **Ответы:**
* `201 Created` — `{ "id": 1, "username": "gardener_1", "createdAt": "..." }`
* `400 Bad Request` — имя пользователя или пароль не переданы.
* `409 Conflict` — никнейм уже занят.



#### `POST /users/login`

* **Назначение:** Авторизация и загрузка профиля с привязанными растениями.
* **Тело запроса:**
```json
{
  "username": "gardener_1",
  "password": "secret_password"
}

```


* **Ответы:**
* `200 OK` — объект профиля со списком растений: `{ "id": 1, "username": "gardener_1", "createdAt": "...", "plants": [...] }`
* `401 Unauthorized` — неверный логин или пароль.



#### `GET /users/{id}`

* **Назначение:** Получение данных пользователя и его растений по идентификатору.
* **Ответы:**
* `200 OK` — профиль с вложенным массивом `plants`.
* `404 Not Found` — пользователь не найден.



---

### 2. Растения (`/plants`)

#### `GET /plants`

* **Назначение:** Загрузка списка растений для отображения на дашборде фронтенда или в меню бота.
* **Параметры строки запроса (Query):**
* `userId` (опционально) — фильтрация по владельцу (например: `?userId=1`).


* **Ответы:**
* `200 OK` — массив объектов `[{ id, name, species, minMoisture, maxMoisture, minTemp, maxTemp, minLight, createdAt, userId }]`.



#### `POST /plants`

* **Назначение:** Создание нового растения с настройкой допустимых порогов жизнедеятельности.
* **Тело запроса:**
```json
{
  "name": "Монстера",
  "species": "Monstera deliciosa",
  "minMoisture": 30.0,
  "maxMoisture": 70.0,
  "minTemp": 18.0,
  "maxTemp": 28.0,
  "minLight": 300.0,
  "userId": 1
}

```


* **Ответы:**
* `201 Created` — созданный объект растения.
* `400 Bad Request` — указан несуществующий `userId`.



#### `POST /plants/{id}/water`

* **Назначение:** Регистрация факта полива. Вызывается по кнопке «Полить» на фронтенде или инлайн-кнопке бота. Автоматически закрывает открытые инциденты сухости почвы и отправляет событие в WebSocket.
* **Тело запроса:** отсутствует.
* **Ответы:**
* `200 OK` — `{ "message": "Полив для рослини '...' успішно зафіксовано." }`
* `404 Not Found` — растение с указанным `id` не найдено.

### 3. Телеметрия (`/telemetry`)

#### `POST /telemetry`

* **Назначение:** Прием пакета данных с датчиков. Вызывается IoT-эмулятором каждые 5–10 секунд.
* **Тело запроса:**
```json
{
  "plantId": 1,
  "moisture": 45.2,
  "temperature": 22.0,
  "light": 450.0,
  "timestamp": "2026-10-08T17:00:00Z"
}

```


*(Поле `timestamp` опционально. Если передано `null` или опущено, бэкенд выставляет текущее системное время в UTC).*
* **Поведение бэкенда:** сохраняет замер, проверяет пороги растения, при выходе за пределы создает алерт и рассылает обновления через SignalR.
* **Ответы:**
* `200 OK` — сохраненная запись телеметрии.
* `404 Not Found` — растение с указанным `plantId` не найдено.



#### `GET /telemetry/{plantId}/history`

* **Назначение:** Получение истории замеров для отрисовки графиков (фронтенд) или получения актуального состояния для команды бота `/status`.
* **Параметры строки запроса (Query):**
* `limit` (int, по умолчанию 50) — максимальное число записей.
* `days` (int, опционально) — выборка за последние N дней.
* `hours` (int, опционально) — выборка за последние N часов.
* `from` (ISO date, опционально) — начальная граница выборки.
* `to` (ISO date, опционально) — конечная граница выборки.


* **Порядок сортировки:** строго от новых к старым (`OrderByDescending(Timestamp)`). Самая свежая запись всегда находится под индексом `[0]`.
* **Ответы:**
* `200 OK` — массив объектов `[{ id, plantId, moisture, temperature, light, timestamp }]`.

### 4. Алерты и инциденты (`/alerts`)

#### `GET /alerts/active`

* **Назначение:** Получение списка всех незакрытых аварий для отображения предупреждающих плашек в интерфейсе.
* **Параметры строки запроса (Query):**
* `plantId` (int, опционально) — фильтрация по конкретному растению.


* **Ответы:**
* `200 OK` — массив объектов `[{ id, plantId, plantName, type, message, createdAt, isResolved, resolvedAt }]`.



#### `PUT /alerts/{id}/resolve`

* **Назначение:** Ручное закрытие аварии.
* **Тело запроса:** отсутствует.
* **Ответы:**
* `204 NoContent` — инцидент успешно закрыт.
* `400 Bad Request` — инцидент уже был закрыт ранее.
* `404 Not Found` — инцидент с указанным `id` не существует.



#### Коды типов алертов (Enum `type`):

* `0` (`LowMoisture`) — низкая влажность почвы (требуется полив).
* `1` (`HighMoisture`) — переувлажнение почвы.
* `2` (`LowTemperature`) — критически низкая температура.
* `3` (`HighTemperature`) — превышение температурной нормы.
* `4` (`LowLight`) — недостаточный уровень освещенности.

### 5. WebSocket / SignalR (`/hubs/telemetry`)

Клиенты (веб-интерфейс и скрипт бота) подключаются к хабу `/hubs/telemetry` и регистрируют обработчики следующих событий:

#### Событие `ReceiveTelemetry`

* **Когда отправляется:** при каждом успешном запросе `POST /telemetry`.
* **Кто слушает:** Фронтенд (добавляет точку на график без перезагрузки экрана).
* **Структура объекта (Payload):**
```json
{
  "id": 128,
  "plantId": 1,
  "moisture": 42.5,
  "temperature": 23.1,
  "light": 420.0,
  "timestamp": "2026-10-08T17:05:00Z"
}

```



#### Событие `ReceiveAlert`

* **Когда отправляется:** в момент фиксации критического отклонения от нормы (при условии, что аналогичный алерт для этого растения еще не открыт).
* **Кто слушает:** Фронтенд (всплывающее модальное окно/тост), Telegram-бот (мгновенная отправка пуш-сообщения пользователю с инлайн-кнопкой полива).
* **Структура объекта (Payload):**
```json
{
  "id": 15,
  "plantId": 1,
  "plantName": "Монстера",
  "type": 0,
  "message": "Низька вологість: 24.5% (мінімум: 30.0%)",
  "createdAt": "2026-10-08T17:05:00Z",
  "isResolved": false,
  "resolvedAt": null
}

```



#### Событие `ReceiveWatering`

* **Когда отправляется:** при вызове `POST /plants/{id}/water`.
* **Кто слушает:** Фронтенд и Telegram-бот (синхронизация состояния анимации полива).
* **Структура объекта (Payload):**
```json
{
  "plantId": 1,
  "timestamp": "2026-10-08T17:06:12Z"
}

```
