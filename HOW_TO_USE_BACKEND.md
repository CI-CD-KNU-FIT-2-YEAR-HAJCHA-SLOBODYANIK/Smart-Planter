### Базовые адреса и протоколы

* REST API (Docker): `http://localhost:8000/api/v1`
* REST API (Local): `http://localhost:5168/api/v1`
* WebSocket Hub (SignalR): `/hubs/telemetry?access_token=<JWT_TOKEN>`
* Формат обмена данными: `application/json`
* Формат дат: ISO 8601 UTC (`YYYY-MM-DDTHH:mm:ssZ`)
* Аутентификация:
* **Пользователи (Web / Telegram-бот):** Заголовок `Authorization: Bearer <JWT_TOKEN>`.
* **IoT-устройства и эмуляторы датчиков:** Заголовок `X-Device-Key: <DEVICE_API_KEY>`.

### 1. Пользователи (`/users`)

#### `POST /users/register`

* **Назначение:** Регистрация пользователя с выдачей JWT-токена. Фронтенд вызывает при создании аккаунта, Telegram-бот — при первом старте (`/start`), генерируя пароль автоматически.
* **Тело запроса:**

```json
{
  "username": "gardener_1",
  "password": "secret_password"
}

```

* **Ответы:**
* `201 Created` — профиль с выданным JWT-токеном:



```json
{
  "id": 1,
  "username": "gardener_1",
  "createdAt": "2026-10-08T17:00:00Z",
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "plants": null
}

```

* `400 Bad Request` — имя пользователя или пароль пустые (`"Ім'я користувача та пароль не можуть бути порожніми."`).
* `409 Conflict` — никнейм уже занят (`"Користувач із нікнеймом '...' вже зареєстрований."`).

#### `POST /users/login`

* **Назначение:** Аутентификация пользователя, генерация JWT-токена и выгрузка списка личных растений вместе с их API-ключами устройств.
* **Тело запроса:**

```json
{
  "username": "gardener_1",
  "password": "secret_password"
}

```

* **Ответы:**
* `200 OK` — профиль с токеном и списком растений:



```json
{
  "id": 1,
  "username": "gardener_1",
  "createdAt": "2026-10-08T17:00:00Z",
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "plants": [
    {
      "id": 1,
      "name": "Монстера",
      "species": "Monstera deliciosa",
      "apiKey": "e4d909c290d0468ea9c8f074d2a10582",
      "minMoisture": 30.0,
      "maxMoisture": 70.0,
      "minTemp": 18.0,
      "maxTemp": 28.0,
      "minLight": 300.0,
      "createdAt": "2026-10-08T17:00:00Z"
    }
  ]
}

```

* `401 Unauthorized` — неверный логин или пароль (`"Невірне ім'я користувача або пароль."`).

#### `GET /users/me`

* **Назначение:** Получение данных текущего пользователя по его JWT-токену.
* **Заголовки:** `Authorization: Bearer <JWT_TOKEN>` (обязателен).
* **Ответы:**
* `200 OK` — профиль авторизованного пользователя со списком его растений:



```json
{
  "id": 1,
  "username": "gardener_1",
  "createdAt": "2026-10-08T17:00:00Z",
  "token": null,
  "plants": [...]
}

```

* `401 Unauthorized` — токен отсутствует, просрочен или некорректен.
* `404 Not Found` — пользователь не найден в базе данных.

#### `GET /users/{id}`

* **Назначение:** Получение публичных данных пользователя по числовому идентификатору.
* **Ответы:**
* `200 OK` — публичный профиль с массивом растений.
* `404 Not Found` — пользователь с указанным ID не найден.

### 2. Растения (`/plants`)

Все методы контроллера изолированы: работа происходит строго в рамках учетной записи из переданного JWT-токена.

#### `GET /plants`

* **Назначение:** Загрузка списка растений текущего авторизованного пользователя.
* **Заголовки:** `Authorization: Bearer <JWT_TOKEN>` (обязателен).
* **Ответы:**
* `200 OK` — массив объектов растений, принадлежащих пользователю:



```json
[
  {
    "id": 1,
    "name": "Монстера",
    "species": "Monstera deliciosa",
    "apiKey": "e4d909c290d0468ea9c8f074d2a10582",
    "minMoisture": 30.0,
    "maxMoisture": 70.0,
    "minTemp": 18.0,
    "maxTemp": 28.0,
    "minLight": 300.0,
    "createdAt": "2026-10-08T17:00:00Z"
  }
]

```

* `401 Unauthorized` — отсутствие или невалидность токена.

#### `POST /plants`

* **Назначение:** Создание нового растения с генерацией уникального `apiKey` для IoT-датчика. Растение автоматически привязывается к текущему пользователю.
* **Заголовки:** `Authorization: Bearer <JWT_TOKEN>` (обязателен).
* **Тело запроса:**

```json
{
  "name": "Монстера",
  "species": "Monstera deliciosa",
  "minMoisture": 30.0,
  "maxMoisture": 70.0,
  "minTemp": 18.0,
  "maxTemp": 28.0,
  "minLight": 300.0
}

```

* **Ответы:**
* `201 Created` — созданное растение со сгенерированным `apiKey` (передается датчику/эмулятору):



```json
{
  "id": 1,
  "name": "Монстера",
  "species": "Monstera deliciosa",
  "apiKey": "e4d909c290d0468ea9c8f074d2a10582",
  "minMoisture": 30.0,
  "maxMoisture": 70.0,
  "minTemp": 18.0,
  "maxTemp": 28.0,
  "minLight": 300.0,
  "createdAt": "2026-10-08T17:00:00Z"
}

```

* `401 Unauthorized` — запрос без авторизации.

#### `POST /plants/{id}/water`

* **Назначение:** Регистрация факта полива. Закрывает активные предупреждения сухости (`LowMoisture`) и отправляет событие `ReceiveWatering` в WebSocket владельца.
* **Заголовки:** `Authorization: Bearer <JWT_TOKEN>` (обязателен).
* **Тело запроса:** отсутствует.
* **Ответы:**
* `200 OK` — `{ "message": "Полив для рослини '...' успішно зафіксовано." }`
* `401 Unauthorized` — запрос без авторизации.
* `404 Not Found` — растение не найдено или принадлежит другому пользователю.

### 3. Телеметрия (`/telemetry`)

#### `POST /telemetry`

* **Назначение:** Прием пакета данных от физического IoT-устройства или эмулятора. Идентификация растения выполняется по аппаратному ключу.
* **Заголовки:** `X-Device-Key: <DEVICE_API_KEY>` (обязателен).
* **Тело запроса:**

```json
{
  "moisture": 45.2,
  "temperature": 22.0,
  "light": 450.0,
  "timestamp": "2026-10-08T17:00:00Z"
}

```

*(Поле `timestamp` опционально. Если передано `null` или опущено, бэкенд выставляет текущий системный UTC).*

* **Поведение бэкенда:** находит растение по `X-Device-Key`, сохраняет замер, проверяет пороговые значения, при выходе за границы создает алерты и отправляет события в SignalR **строго владельцу этого растения**.
* **Ответы:**
* `200 OK` — подтверждение сохранения замера:



```json
{
  "id": 105,
  "plantId": 1,
  "moisture": 45.2,
  "temperature": 22.0,
  "light": 450.0,
  "timestamp": "2026-10-08T17:00:00Z"
}

```

* `401 Unauthorized` — заголовок `X-Device-Key` не передан или передан несуществующий ключ.

#### `GET /telemetry/{plantId}/history`

* **Назначение:** Выборка истории замеров для графиков на клиенте или команды `/status` в боте.
* **Заголовки:** `Authorization: Bearer <JWT_TOKEN>` (обязателен).
* **Параметры строки запроса (Query):**
* `limit` (int, по умолчанию `50`) — максимальное количество записей в выборке.
* `days` (int, опционально) — срез за последние N дней от текущего момента.
* `hours` (int, опционально) — срез за последние N часов от текущего момента.
* `from` (ISO date, опционально) — нижняя граница времени UTC.
* `to` (ISO date, опционально) — верхняя граница времени UTC.


* **Сортировка:** От новых к старым (`OrderByDescending(t => t.Timestamp)`). Самый свежий замер всегда находится под индексом `[0]`.
* **Ответы:**
* `200 OK` — массив объектов `[{ id, plantId, moisture, temperature, light, timestamp }]`.
* `401 Unauthorized` — запрос без авторизации.
* `404 Not Found` — растение не найдено либо принадлежит другому пользователю.

### 4. Алерты и инциденты (`/alerts`)

Все методы контроллера изолированы: пользователь видит и закрывает алерты только своих растений.

#### `GET /alerts/active`

* **Назначение:** Получение списка всех неразрешенных инцидентов текущего пользователя.
* **Заголовки:** `Authorization: Bearer <JWT_TOKEN>` (обязателен).
* **Параметры строки запроса (Query):**
* `plantId` (int, опционально) — фильтрация по конкретному растению пользователя.


* **Ответы:**
* `200 OK` — массив активных инцидентов:



```json
[
  {
    "id": 15,
    "plantId": 1,
    "plantName": "Монстера",
    "type": 0,
    "message": "Низька вологість: 24.5% (мінімум: 30.0%)",
    "createdAt": "2026-10-08T17:05:00Z",
    "isResolved": false,
    "resolvedAt": null
  }
]

```

* `401 Unauthorized` — запрос без авторизации.

#### `PUT /alerts/{id}/resolve`

* **Назначение:** Ручное закрытие аварии пользователем.
* **Заголовки:** `Authorization: Bearer <JWT_TOKEN>` (обязателен).
* **Тело запроса:** отсутствует.
* **Ответы:**
* `204 NoContent` — инцидент успешно закрыт.
* `400 Bad Request` — инцидент уже был закрыт ранее (`"Інцидент вже був закритий раніше."`).
* `401 Unauthorized` — запрос без авторизации.
* `404 Not Found` — инцидент не существует или принадлежит растению другого пользователя.



#### Коды типов алертов (`AlertType`):

* `0` (`LowMoisture`) — недостаточная влажность почвы (требуется полив).
* `1` (`HighMoisture`) — избыточная влажность (перелив).
* `2` (`LowTemperature`) — критически низкая температура.
* `3` (`HighTemperature`) — превышение температурной нормы.
* `4` (`LowLight`) — недостаточный уровень освещенности.

### 5. WebSocket / SignalR (`/hubs/telemetry`)

Подключение клиентов (фронтенд и Telegram-бот) выполняется по URL с передачей токена в строке запроса:
`/hubs/telemetry?access_token=<JWT_TOKEN>`

Все события отправляются адресно владельцу (`Clients.User(userId)`). Сторонние пользователи чужие события не получают.

#### Событие `ReceiveTelemetry`

* **Триггер:** Успешный запрос `POST /telemetry` от датчика.
* **Получатель:** Фронтенд владельца растения (добавление точки на график без перезагрузки страницы).
* **Структура Payload:**

```json
{
  "id": 128,
  "plantId": 1,
  "moisture": 42.5,
  "temperature": 23.1,
  "light": 420.0,
  "timestamp": "2026-10-08T17:05:00Z"
}

```

#### Событие `ReceiveAlert`

* **Триггер:** Фиксация критического отклонения от нормы при отсутствии аналогичного незакрытого алерта.
* **Получатель:** Telegram-бот владельца (мгновенный пуш с инлайн-кнопкой полива) и веб-интерфейс (всплывающее предупреждение).
* **Структура Payload:**

```json
{
  "id": 15,
  "plantId": 1,
  "plantName": "Монстера",
  "type": 0,
  "message": "Низька вологість: 24.5% (мінімум: 30.0%)",
  "createdAt": "2026-10-08T17:05:00Z",
  "isResolved": false,
  "resolvedAt": null
}

```

#### Событие `ReceiveWatering`

* **Триггер:** Успешный вызов эндпоинта `POST /plants/{id}/water`.
* **Получатель:** Клиенты владельца растения (синхронизация состояния и обновление UI).
* **Структура Payload:**

```json
{
  "plantId": 1,
  "timestamp": "2026-10-08T17:06:12Z"
}

```
