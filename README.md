# Smart-Planter

Система моніторингу стану рослин на базі ASP.NET Core та PostgreSQL.

## Системні вимоги

- Docker Desktop (з підтримкою `docker compose`)
- Git
- .NET SDK (необхідний для локального запуску автотестів)

---

## Швидкий запуск

1. **Клонування репозиторію та перехід у папку:**

   git clone https://github.com/CI-CD-KNU-FIT-2-YEAR-HAJCHA-SLOBODYANIK/Smart-Planter.git smart-planter
   cd smart-planter

2. **Запуск сервісів (Backend + PostgreSQL):**

   docker compose up -d --build

3. **Доступ до сервісів:**

   Документація API (Scalar): http://localhost:8000/scalar/v1
   Специфікація OpenAPI: http://localhost:8000/openapi/v1.json
   WebSocket Hub (SignalR): http://localhost:8000/hubs/telemetry
   База даних: localhost:5432
   БД: smart_planter
   Користувач: postgres
   Пароль: postgres_secure_pass

4. **Зупинка:**

   **Зупинити роботу контейнерів:**

   docker compose down

   **Зупинити та видалити збережені дані бази (скидання стану):**

   docker compose down -v

## Backend та Автотести

1. **Запуск юніт-тестів (виконується з кореня репозиторію):**

   dotnet test

   **Тестовий набір перевіряє:**
   - Генерацію та цілісність сутностей рослин при поодинокому та масовому створенні.
   - Збереження черги телеметрії та перевірку історії вибірки (із рандомізованим перемішуванням).
   - Спрацьовування тривог для всіх комбінацій параметрів (бітові маски сенсорів вологості, температури й світла).
   - Захист від дублювання відкритих інцидентів при повторному надходженні критичних значень.
   - Повний життєвий цикл інциденту (створення -> закриття через API -> генерація нового при повторному відхиленні).
   - Трансляцію подій у режимі реального часу через SignalR (вебсокети).

2. **Стрімінг даних у реальному часі (SignalR):**
   - Точка підключення: `/hubs/telemetry`
   - Подія трансляції: `ReceiveTelemetry`
   - Модель даних: об'єкт із полями `id`, `plantId`, `moisture`, `temperature`, `light`, `timestamp`.

3. **CI/CD:**
   - Автоматичний пайплайн налаштовано у GitHub Actions (`.github/workflows/backend-ci.yml`).
   - Відновлення залежностей, компіляція та прогін юніт-тестів виконуються автоматично при кожному `push` та `pull request` у гілку `main`.

## Frontend

0. **Обов'язково переконатись, що бекенд запущений, тому що без нього фронтенд не зможе працювати**

1. **Завантажити пакети:**

   npm install

2. **Переключити папку на фронтенд:**

   cd frontend

3. **Запустити фронтенд сторінку: (Щоб перейти на сторінку, наведіться на посилання локалхост мишкою і нажміть CTRL + L Mouse (ліва кнопка миші))**

   npm run dev

4. **Зупинити роботу сторінки в терміналі:**

   CTRL + C

5. **Офлайн**

   **Спочатку запустити дві команди водночас або одна за одною**

   npm run build

   npx vite preview

   **Потім, щоб перевірити офлайн режим**

   Зайти в "Inspect" (через праву кнопку миші), де знаходяться dev tools

   Нажати вкладку "Network" і змінити No throttling -> Offline

   Якщо сторінка не чисто біла, значить все працює
